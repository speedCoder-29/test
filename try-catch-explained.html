Try / Catch Explained

A complete guide to error handling in JavaScript

1What is Try/Catch?

try/catch is JavaScript's way of handling errors gracefully. Instead of your program crashing when something goes wrong, you can catch the error and decide what to do about it.

Think of it like a safety net. If a tightrope walker (your code) falls, the net (catch) is there to prevent disaster.

try {
  // Code that might fail
  riskyOperation();
} catch (error) {
  // Runs ONLY if something broke above
  console.log("Error:", error.message);
}

2How Does It Flow?

If the code succeeds:

try block runs
→
Code works!
→
catch is SKIPPED
→
Program continues

If the code fails:

try block runs
→
Error thrown!
→
catch runs
→
Program continues

The key takeaway: your program keeps running either way. Without try/catch, an error would crash everything.

5Finally Block

The finally block runs no matter what — whether the code succeeded or failed. It's useful for cleanup tasks.

try {
  openFile();
  readData();
} catch (error) {
  console.log("Failed to read file");
} finally {
  // Always runs - success or failure
  closeFile();
}
try
→
catch (if error)
→
finally (ALWAYS)

6Throwing Your Own Errors

You can use throw to create your own errors. This is useful for validating data:

function divide(a, b) {
  if (b === 0) {
    throw new Error("Cannot divide by zero!");
  }
  return a / b;
}

try {
  divide(10, 0);
} catch (error) {
  console.log(error.message); // "Cannot divide by zero!"
}

8Real-World Examples in Your Projects

Calculator — evaluating user expressions:

try {
  let result = Function('"use strict"; return (' + expression + ')')();
  current = String(result);
} catch {
  current = "Error"; // Show "Error" instead of crashing
}

Login System — parsing stored session data:

try {
  const user = JSON.parse(sessionStorage.getItem("loggedInUser"));
  // Use user data...
} catch (error) {
  // Corrupt data? Redirect to login
  window.location.href = "login.html";
}
Tip: Don't wrap everything in try/catch. Only use it around code that can genuinely fail (user input, JSON parsing, network requests, file operations). Using it everywhere hides bugs that should be fixed.
